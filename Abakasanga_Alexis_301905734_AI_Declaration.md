# AI Use Declaration (MIT 8103 portfolio)

**1. AI tools used**
- **Claude (Anthropic):** main learning aid and drafting assistant for this submission.
- **Google NotebookLM / Gemini:** used briefly for an earlier draft on a different case study (ShopQuick). None of that draft is used in this submission.

**2. What Claude was used for**
- Explaining concepts I was new to: normalisation, keys and constraints, execution plans and indexing, transactions and isolation levels, document modelling, replication and CAP.
- Drafting the first versions of the case study, SQL and mongosh scripts, the ER and architecture diagram sources, and the README files.
- Step-by-step guidance for installing and running PostgreSQL, Git, MongoDB Atlas and mongosh on my Windows laptop.
- Fixing problems that came up when I ran the scripts (see below).
- Drafting the wording of the analysis sections from my own measured results, which I then reviewed.

**3. How I reviewed, tested and verified the work**
- I installed PostgreSQL 18.6, pgAdmin, Git, mongosh 2.14.2 and a MongoDB Atlas free cluster myself and ran **every script** on my own machine. All screenshots and text outputs in the `evidence/` folders come from those runs, and all timings and counts in the READMEs are my measurements.
- Running the scripts exposed real problems that we fixed and re-tested:
  - The bulk-data script failed with a foreign-key error because a deliberately failed insert in my Portfolio 1 constraint tests had used up technician ID 8. The script now picks technicians by position instead of by ID.
  - Query labels were not appearing in my saved plan files (`\echo` vs `\qecho`), so the scripts were corrected.
  - The MongoDB explain summary did not handle the MongoDB 8 plan format and was updated.
- My results differed from the original expectations, and the analysis was rewritten to match what I actually saw. For example, PostgreSQL 18 used a skip scan on the existing index before I added my own indexes.
- My first SERIALIZABLE test ran in the wrong order and showed no error. I worked out why (both sessions must read before either writes), repeated it correctly and recorded it.
- I can explain each design decision and result in this repository.

I remain responsible for the accuracy, originality and understanding of the submitted work.

**Other resources acknowledged:** PostgreSQL and MongoDB official documentation; the MIT 8103 lecture slides and readings. All data in this repository is fictional and generated by the scripts provided.
